## 目的と動機
フレームワークを使わずにエージェントの最小構成(LLM → ツール → 結果 → 繰り返し)を自作し、仕組みを理解する。題材はこのリポジトリの文書(正解が明確)。

## 必要な能力・ツール
商用 LLM API(Tool Calling)/ `list_dir`・`read_file`(リポジトリ内のみ)/ エージェントループ・パス許可リスト・トレース

## 受け入れ基準(Acceptance criteria)
- [ ] 開発言語を決めて ADR を作成(OPEN_ISSUES Q-06)
- [ ] 正解の分かる質問 10 問で正答 9 問以上
- [ ] 全回答で参照ファイルパスを提示
- [ ] ツール呼び出しの 100% がトレースに記録
- [ ] 許可範囲外の読み取り要求 3/3 をプログラム側で拒否
- [ ] 試験前後の SHA-256 一覧が完全一致

## 詳細(実装の概要・試験手順)
[Phase 1 試験計画 §P1-1](https://github.com/Hiroto-Masaoka/AI-agents-family/blob/main/docs/EXPERIMENTS/PHASE1_TEST_PLAN.md#p1-1-最小エージェントリポジトリの文書に答える)

## 共通ルール(Read-Only)
- エージェントに書き込み・削除・任意のシェル/コード実行・POST 系 API のツールを与えない([ADR-0009](https://github.com/Hiroto-Masaoka/AI-agents-family/blob/main/docs/DECISIONS/ADR-0009-phase1-read-only-policy.md))
- 読み取り範囲は許可リストでプログラム側から制限する。出力は標準出力
- 試験前後で対象ディレクトリの SHA-256 一覧が一致することを確認する
