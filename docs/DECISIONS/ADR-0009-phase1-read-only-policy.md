# ADR-0009: Phase 1 のエージェントは厳密に読み取り専用とし、プログラム側で強制する

- **Status:** Decided(読み取り専用とすること)/ 強制方法の詳細は Proposed
- **日付:** 2026-11-16
- **決定者:** 開発者(読み取り専用の要件)、強制方法は AI 提案
- **関連:** [PHASE1_TEST_PLAN §1](../EXPERIMENTS/PHASE1_TEST_PLAN.md#1-全タスク共通のルールread-only)、ADR-0006

## 背景
Phase 1 は仕組みを学ぶ段階であり、エージェントの誤動作でファイル・システム・外部サービスに影響が出ることを避けたい。開発者は Phase 1 を「ファイル変更、システム変更、外部への書き込みを一切しない」と定めた。

## 決定
1. **書き込み能力をツールとして与えない。** 書き込み・削除・任意のシェル実行・コード実行・POST/PUT/DELETE 系の API はツールに含めない。指示文で「書かないで」と頼むのではなく、存在させない。
2. **読み取り範囲を許可リストで制限する。** ファイルは許可ディレクトリ内のみ、通信は許可したホストへの GET のみ。
3. **出力は標準出力に出す。**
4. **例外(提案):** エージェントではなくハーネス(決定論的なプログラム)が、試験記録のためのトレースを `logs/runtime/`(`.gitignore` 済み)に書くことだけを認める。これを認めない場合は、トレースも標準出力に出してコピーする運用とする。
5. **検証する。** 各試験の前後で対象ディレクトリの SHA-256 一覧を比較し、MCP サーバーなどの公開ツール一覧を監査する。

## 適用範囲
エージェントが **実行時に取る行動** に適用する。エージェントのプログラム自体を開発・コミットすることは通常の開発作業であり、対象外。

## 理由
- LLM はツールを「呼びたい」と出力するだけで、実行するのはプログラムであるため、能力を与えなければ確実に防げる(BASICS §2)。
- 指示文による制限は破られることがある(公開事例の知見、references 参照)。

## トレードオフ
- コードを実行して検証する、ファイルに結果を保存する、といった便利な機能は Phase 2 まで使えない。
