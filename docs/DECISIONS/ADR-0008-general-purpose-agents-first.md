# ADR-0008: 当面は日常業務・研究を支援する汎用 AI-Agent を優先し、望遠鏡固有の開発は延期する

- **Status:** Decided
- **日付:** 2026-11-16
- **決定者:** 開発者
- **関連:** LOG-20261116-03、[ADR-0003](ADR-0003-first-target-daily-operations.md)(本 ADR により一部置き換え)、[PHASE1_TEST_PLAN](../EXPERIMENTS/PHASE1_TEST_PLAN.md)

## 背景
ADR-0003 では最初の目標を「日常的な観測運用の自動化」とした。しかし AI-Agent 開発は初めてであり、望遠鏡の運用には装置仕様・制御方式などの準備が必要で、失敗の影響も大きい。まずは身近な業務で、エージェントの仕組みを実際に作って学ぶことを優先する。

## 選択肢
1. 望遠鏡の運用自動化から始める(ADR-0003 のまま)
2. **日常業務・研究を支援する汎用エージェントから始め、望遠鏡は後のフェーズで扱う** ← 採用

## 決定
当面の目標を、次の用途で実用的な AI-Agent を作ることとする。
- コーディング・ソフトウェア開発
- 研究・文献調査
- データ分析・ドキュメント作成
- 定型作業の自動化
- 研究資金の公募調査・申請支援
- 正当な(合法かつ倫理的な)AI を活用した収益機会の調査

学ぶべき要素:エージェントの構成、ツール連携、メモリ、ワークフロー、マルチエージェントの協調、評価。
進め方:作りながら学ぶ反復型(ADR-0002 を継続)。

望遠鏡のハードウェア仕様・制御インターフェースの確認は、将来の観測所運用システムの開発フェーズまで保留する。

## 理由
- 正解が分かる身近な題材のほうが、評価がしやすく学習が速い。
- ここで作るツール接続・メモリ・検証・評価の仕組みは、将来の観測運用にもそのまま使える(装置インターフェースを差し替えるだけにする設計方針、ARCHITECTURE §4)。
- 失敗の影響が小さい。

## トレードオフ
- 望遠鏡の自動化・FRB 追観測の実現は後になる。

## ADR-0003 との関係
ADR-0003 の「最初の目標」は本 ADR で置き換える。「観測運用の自動化」自体は将来の目標として維持する(ROADMAP Phase 5 以降)。
