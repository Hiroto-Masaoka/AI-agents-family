# 1. プロジェクトの背景と開発方針

現在、以下のようなAI-Agentの開発を構想しています。

- 対象システム：自前の電波望遠鏡
- 最初の目標：日常的な電波望遠鏡の観測運用の自動化
- 将来的な目標：観測システムの長期的な自律運用と、FRBなどの突発天体に対する自動追観測

- 開発者の経験：AI-Agent開発は初めて
- 開発方針：小さく実装・試験・評価を繰り返しながら段階的に拡張する

将来的には、電波望遠鏡だけでなく、X線衛星などの観測システムにも応用できる汎用的なAI-Agentの開発を視野に入れています。

以下の観点を検討してください。

今後の開発で一貫性を保つため、以下のルールを定めてください。

個人開発でも運用負荷が大きくならない、シンプルで実用的なルールを優先してください。

## 2.3 開発ログの標準化

特に重要視している項目です。

今後、Claude CodeなどのAIを利用して開発する際に、以下の情報が後から追跡できる仕組みを構築してください。

1. 何を実現しようとしたのか
2. なぜその開発が必要だったのか
3. どのような技術・手法を採用したのか
4. どのような実装・変更を行ったのか
5. どのような試験を実施したのか
6. 試験結果はどうだったのか
7. 問題が発生した場合、その原因は何だったのか
8. 何が分かり、どのような知見が得られたのか
9. 次に何を実施するべきなのか

単なる作業履歴ではなく、技術的な意思決定や失敗から得られた知見も残せるようにしてください。

また、AI-Agent開発の初心者が読んでも理解できるよう、専門用語については必要に応じて説明を加えるルールにしてください。

# 4. ドキュメント作成ルール

すべてのドキュメントは、原則としてMarkdown形式で作成してください。

以下の原則を守ってください。

## 4.1 初心者にも理解できる記述

- 専門用語は初出時に説明する
- 技術を採用した理由を明記する
- 技術的な選択肢がある場合は比較する
- 単に結論を書くのではなく、背景や考え方も残す
- 必要に応じて図やMermaidによる構成図を使用する

## 4.2 情報の信頼性

情報は以下のように分類してください。

- Confirmed：実装・試験などで確認済み
- Decided：方針として決定済み
- Proposed：提案・検討中
- Planned：今後実施予定
- Unverified：未検証・未確認

推測やAIによる補完を事実として記録しないでください。

不明な情報は「未確認」と明記してください。

## 4.3 開発履歴の追跡性

技術的な変更や重要な意思決定について、以下を記録してください。

- 日付
- 変更内容
- 変更理由
- 関連するIssueやファイル
- 試験結果
- 影響範囲

また、過去の記録を不用意に書き換えず、変更が発生した場合は履歴として追跡できるようにしてください。

3. `docs/ARCHITECTURE.md`
   - システム全体の構成
   - 各コンポーネントの役割
   - データ・処理の流れ
   - 現時点の構想と将来構想の区別

4. `docs/DEVELOPMENT_GUIDELINES.md`
   - Git運用
   - Commit規則
   - Issue管理
   - ドキュメント管理
   - 開発ログのルール

5. `docs/ROADMAP.md`
   - 開発フェーズ
   - 各フェーズの目標
   - 完了条件
   - 優先順位

6. `docs/TECH_STACK.md`
   - 採用済み技術
   - 導入候補技術
   - 技術選定理由
   - 比較検討事項

7. `docs/DEVELOPMENT_LOG.md`
   - 現時点までの開発・議論の履歴
   - 重要な意思決定

8. `docs/EXPERIMENTS/`
   - 個別の実験・試験記録
   - 実験目的
   - 試験条件
   - 実施手順

   - トレードオフ

必要に応じて、これ以外のファイルやディレクトリも追加してください。

# 6. 実際の作業手順

以下の順番で作業を進めてください。

**Step 1：現状調査**

- 対象ディレクトリの内容を確認する
- 既存ファイルやGitの状態を調査する
- 既存の情報を不用意に削除・上書きしない
- 既存ドキュメントと今回の構想の重複や矛盾を確認する

**Step 2：管理方針の設計**

- 推奨するディレクトリ構成を決める
- Git運用ルールを決める
- 開発ログ・実験ログのテンプレートを設計する
- ドキュメント間の役割を明確にする

**Step 3：ドキュメントの作成**

- 既存情報を整理する
- 必要なMarkdownファイルを作成する
- 相互にリンクを設定する
- Mermaidなどを用いて構成を可視化する

**Step 4：内容の検証**

- 情報の重複や矛盾がないか確認する
- 実装済みと構想段階の内容が混同されていないか確認する
- リンク切れがないか確認する
- READMEから必要な情報にアクセスできるか確認する

**Step 5：最終報告**

以下を報告してください。

- 作成したディレクトリ構成
- 作成・更新したファイル
- 各ドキュメントの役割
- 現時点で整理できた開発内容
- 未確認・不足している情報
- 今後の開発における推奨事項
- 次に取り組むべきタスク

# 7. 重要な注意事項

- 今回の目的は、GitHubを今後の開発の中心的なナレッジベースにすることです。
- 過剰に複雑な管理システムは作らず、個人開発でも継続できる仕組みにしてください。
- 既存のソースコードや設定ファイルを勝手に変更しないでください。
- 既存の情報を削除しないでください。
- APIキー、パスワード、アクセストークンなどの機密情報をGitHubに記録しないでください。
- 実際に確認できていない内容を事実として記載しないでください。
- GitHubへのPushや既存履歴の書き換えは、私の明示的な許可なしに実行しないでください。
- 不明点がある場合は、勝手に判断せず未確認事項として整理してください。
- 今回はドキュメントと管理基盤の整備を優先し、AI-Agent本体の新規実装には着手しないでください。

**最終的な目標は、今後どのAI（Claude、ChatGPTなど）を利用して開発しても、このGitHubリポジトリを参照することで、プロジェクトの背景・設計思想・これまでの実装・試験結果・今後の課題を正確に理解し、開発を継続できる状態にすることです。**

この方針に従い、まず現状を調査し、その後、実際にリポジトリ内のドキュメントを整備してください。
