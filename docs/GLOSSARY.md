# GLOSSARY — 用語集

AI-Agent 開発の初心者向けに、このリポジトリで使う用語を説明します。新しい用語が出てきたら追加してください(五十音順ではなく分野別)。

## AI・LLM の基本

| 用語 | 説明 |
|------|------|
| **LLM**(Large Language Model、大規模言語モデル) | 大量の文章で学習し、文章を理解・生成する AI モデル。Claude、GPT、Gemini、Llama など。AI-Agent の「頭脳」にあたる。 |
| **プロンプト**(Prompt) | LLM に与える指示文。 |
| **システムプロンプト** | 会話の最初に与える、LLM の役割やルールを定める指示文。 |
| **トークン**(Token) | LLM が文章を処理する単位(単語の断片程度)。API の料金や処理量はトークン数で決まる。 |
| **コンテキストウィンドウ**(Context window) | LLM が一度に読める情報量の上限(トークン数)。これを超えた情報は「忘れる」。 |
| **ハルシネーション**(Hallucination) | LLM がもっともらしいが事実でない内容を生成すること。本プロジェクトで信頼性ラベルを使う理由の一つ。 |
| **商用 API** | 企業が提供する LLM をインターネット経由で呼び出すサービス(例:Anthropic API、OpenAI API)。高性能だが従量課金で、データが外部に送られる。 |
| **ローカル LLM** | 自前の計算機上で動かす LLM(例:Llama、Qwen などの公開モデル)。データが外に出ず、通信なしで動くが、性能は計算機に依存する。 |
| **推論**(Inference) | 学習済みモデルを使って答えを出すこと(学習とは別)。 |
| **ファインチューニング**(Fine-tuning) | 既存モデルを追加データで再学習し、特定用途に合わせること。本プロジェクトでは現時点で予定なし。 |
| **RAG**(Retrieval-Augmented Generation、検索拡張生成) | 回答前に関連文書を検索して LLM に渡す手法。マニュアルや過去ログを参照させるのに使える。 |
| **埋め込み**(Embedding) | 文章を意味の近さで比較できる数値ベクトルに変換したもの。RAG の検索に使う。 |

## AI-Agent の構成要素

| 用語 | 説明 |
|------|------|
| **AI-Agent**(AI エージェント) | LLM が目的に向かって「考える → ツールを使う → 結果を観察する」を繰り返して作業する仕組み。単なるチャットとの違いは、自分で手順を決め、外部に作用できること。 |
| **エージェントループ**(Agent loop) | 上記の「考える → 行動 → 観察」の繰り返し。 |
| **Tool Calling / Function Calling** | LLM が「この関数をこの引数で呼んで」と構造化された形で出力し、プログラムがそれを実行して結果を返す仕組み。エージェントが外界に作用する唯一の手段。 |
| **ツール**(Tool) | エージェントが呼べる関数。例:「望遠鏡の状態を取得する」「ファイルを読む」。 |
| **MCP**(Model Context Protocol) | LLM アプリとツール・データを接続するための共通規格。一度 MCP サーバーとして作ったツールは、対応する複数の AI から使える。 |
| **ワークフロー**(Workflow) | 手順があらかじめ決まった処理の流れ。エージェントより予測しやすく安全。「決まった手順はワークフロー、判断が必要な部分だけエージェント」が基本。 |
| **オーケストレーター**(Orchestrator) | 複数のエージェントに仕事を割り振り、結果をまとめる司令塔役のエージェント。 |
| **サブエージェント / ワーカー** | オーケストレーターから個別の仕事を任されるエージェント。 |
| **マルチエージェント** | 複数のエージェントが役割分担する構成。強力だが複雑でコストも増える。 |
| **メモリ / 状態管理**(Memory / State) | エージェントが過去の経緯や現在の状況を覚えておく仕組み。LLM 自体は会話をまたいで記憶しないため、ファイルやデータベースに保存する。 |
| **Human-in-the-loop**(HITL、人間参加型) | 重要な判断や操作の前に人間の承認を挟む設計。 |
| **ガードレール**(Guardrail) | エージェントが危険な操作をしないよう、プログラム側で強制する制限。 |
| **評価**(Evaluation, Eval) | 決めた試験課題でエージェントの性能を測ること。 |

## 開発管理

| 用語 | 説明 |
|------|------|
| **Git** | ファイルの変更履歴を管理するツール。 |
| **コミット**(Commit) | 変更をひとまとまりとして履歴に記録すること。 |
| **ブランチ**(Branch) | 本流(main)に影響を与えずに作業するための分岐。 |
| **Pull Request**(PR) | ブランチの変更を main に取り込む前に、内容を確認する GitHub の仕組み。 |
| **Issue** | GitHub 上のタスク・バグ・質問の管理票。 |
| **ADR**(Architecture Decision Record) | 重要な技術的意思決定を「背景・選択肢・決定・理由・トレードオフ」の形で残す記録。`docs/DECISIONS/`。 |
| **セマンティックバージョニング**(SemVer) | `MAJOR.MINOR.PATCH` 形式のバージョン番号の付け方。 |
| **push** | ローカルの履歴を GitHub(リモート)に送ること。本プロジェクトではユーザーの許可制。 |

## 天文・観測

| 用語 | 説明 |
|------|------|
| **FRB**(Fast Radio Burst、高速電波バースト) | ミリ秒程度の非常に短い電波の閃光。発生源の多くは銀河系外。 |
| **突発天体 / トランジェント** | 突然明るくなる、または短時間だけ現れる天体現象。 |
| **追観測**(Follow-up observation) | 突発現象の発見後、別の装置や時間で同じ天体を観測すること。 |
| **トリガー** | 追観測を開始するきっかけとなる通知・検出。 |
| **VOEvent** | 天文の突発現象を機械可読な形で通知するための国際規格。(本プロジェクトでの採用は未定) |
